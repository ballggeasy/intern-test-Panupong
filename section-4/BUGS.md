# BUGS.md — ส่วนที่ 4: Debugging & Code Review

ไฟล์ที่แก้แล้ว: [`tasks.js`](tasks.js)

**ข้อ 1 แก้ในโค้ดแล้ว** ส่วนข้อ 2, 3, 4 **ยังไม่ได้แก้ในโค้ด** (ทำเครื่องหมาย `[ยังไม่แก้]` ไว้ใน `tasks.js`)


# 1. SQL Injection ในคำสั่ง UPDATE (บรรทัด 27) — [แก้แล้ว]

**ปัญหา:** `newStatus` (จาก body) และ `taskId` ถูกต่อเข้า SQL โดยตรง

**ตัวอย่าง:** `newStatus = "Done', assigned_to = '5"` ทำให้ UPDATE เปลี่ยนคอลัมน์อื่นด้วย เช่น มอบหมายงานให้ตัวเอง หรือใส่ `'; DROP TABLE tasks; --` เพื่อรันคำสั่งอื่น

**วิธีแก้:** Parameterized Query `db.query('UPDATE tasks SET status = $1 WHERE id = $2', [newStatus, taskId])` ค่าที่ส่งผ่านพารามิเตอร์ถูกมองเป็นข้อมูลเสมอ ไม่ถูกตีความเป็น SQL

**สถานะ:** แก้แล้ว ทั้ง `newStatus` และ `taskId` ถูกส่งเป็นพารามิเตอร์ ยังเหลือข้อ 2 ที่ `newStatus` ยังไม่ถูกตรวจกับรายการที่อนุญาต (จึงบันทึกค่าอะไรก็ได้ แต่ไม่สามารถแทรก SQL ได้อีก)


# 2. ไม่ตรวจ `newStatus` และ flow ของสถานะ (บรรทัด 26–28) — [ยังไม่แก้ในโค้ด]

**ปัญหา:** โจทย์ระบุว่า endpoint เปลี่ยนสถานะ `To Do` → `Done` แต่โค้ดบันทึก `newStatus` ทุกค่า

**ตัวอย่าง:** Employee ส่ง `newStatus = "Archived"` หรือส่ง `"To Do"` ย้อนกลับ Task ที่ปิดแล้ว ข้อมูลสถานะเสียหายและขัดกับ `CHECK (status IN ('To Do','Done'))` ใน schema (section-2)

**วิธีแก้ที่แนะนำ:** ตรวจกับรายการที่อนุญาต (400 ถ้าไม่ถูกต้อง) และบังคับให้เปลี่ยนได้เฉพาะ `To Do` → `Done` (409 ถ้าไม่เข้าเงื่อนไข)

**สถานะ:** ยังไม่แก้

# 3. Response คืน `task` ที่เป็นข้อมูลก่อนอัปเดต (บรรทัด 31) — [ยังไม่แก้ในโค้ด]

**ปัญหา:** `task` มาจาก SELECT ก่อน UPDATE จึงยังเป็น `status: 'To Do'` ทั้งที่อัปเดตสำเร็จแล้ว

**ผลกระทบ:** Client ที่แสดงผลจาก response จะเห็นสถานะผิด

**วิธีแก้ที่แนะนำ:** ใช้ `UPDATE ... RETURNING ...` แล้วส่งแถวที่อัปเดตแล้วกลับไป

**สถานะ:** ยังไม่แก้

# 4. Race condition ระหว่างตรวจสิทธิ์กับอัปเดต (บรรทัด 14, 23, 27) — [ยังไม่แก้ในโค้ด]

**ปัญหา:** ตรวจสิทธิ์ด้วย SELECT แล้วค่อย UPDATE แยกคำสั่ง โดย UPDATE กรองแค่ `id`

**ตัวอย่าง:** ระหว่างสองคำสั่ง Admin ย้าย Task ไปให้ Employee คนอื่น แต่ Employee คนเดิมยังอัปเดตสำเร็จ ทั้งที่ไม่ใช่เจ้าของแล้ว

**วิธีแก้ที่แนะนำ:** ใส่เงื่อนไขสิทธิ์และสถานะใน `WHERE` ของ UPDATE เอง (`AND status = 'To Do' AND ($isAdmin OR assigned_to = $userId)`) ถ้าไม่มีแถวถูกอัปเดต (`rowCount === 0`) ให้ตอบ 409

**สถานะ:** ยังไม่แก้


# สิ่งที่ยังไม่ได้ทำ 
- `authenticate` middleware ใน `tasks.js` เป็นการสมมติว่ามีอยู่ (`../middleware/auth`) ไม่ได้เขียนให้ เพราะโจทย์ให้แก้เฉพาะ endpoint
- ไม่มี rate limiting และ audit log ซึ่งระบบจริงควรมี
